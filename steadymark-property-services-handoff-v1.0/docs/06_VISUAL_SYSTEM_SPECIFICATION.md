# SteadyMark Visual System Specification v1.0

## Governing sentence

> SteadyMark should look like a capable property-services operation whose confidence comes from structure, material reality, and visible responsibility—not visual noise.

## Visual character

**Architectural field documentation × property materiality × restrained service professionalism**.

Steady, legible, practical, organized, grounded, human, and precise. Not luxury-contractor, startup-SaaS, construction-template, lifestyle-renovation, blue-collar cliché, or industrial theater.

## Colors

- `--sm-surface: #F4EFEA`
- `--sm-graphite: #2E2E2E`
- `--sm-clay: #B2553C`
- `--sm-stone: #C9C2B8`
- `--sm-steel: #8A9399`

Clay is an orientation/action accent, not a prestige signal. Working Surface and Graphite dominate.

## Typography

Canonical communication family: **Manrope**.

Fallback: `Manrope, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`.

Recommended roles:

- Hero/H1: 700
- H2: 700
- H3: 650–700
- Body: 400–450
- Navigation: 550–600
- Label: 600
- Button: 650–700
- Form label: 600
- Input: 450–500

Desktop target ranges:

- Hero 64–72 px
- Major section 38–46 px
- Service title 26–32 px
- Body 17–18 px

Mobile:

- Hero 42–48 px
- Section 30–36 px
- Service title 22–26 px
- Body 16–18 px

Absolute body floor: 16 px.

## Layout

Measured editorial grid. Suggested 12 columns desktop, 8 tablet, 4 conceptual mobile. Maximum content region around 1280–1360 px, with narrower reading measure around 60–75 characters per line.

Suggested horizontal padding:

- Desktop 48–72 px
- Tablet 28–40 px
- Mobile 20–24 px

Vertical rhythm family: 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96 / 128.

## Geometry

Precise rectangles, straight rules, restrained corners, reference ticks, registration gestures, strong alignment. Avoid soft-pill saturation, oversized radii, blobs, gradients, glassmorphism, generic SaaS cards, and blueprint cosplay.

Default radii: 0–4 px structural; 6–8 px where ergonomics benefit.

## Field structure

Alternate broad orientation fields with focused working fields. Use spacing and alignment before borders. Avoid boxing every section.

## Registration mark

Semantic roles:

- Reference
- Connection
- Completion / resulting condition

Do not use as wallpaper, checkmark, universal bullet, or decorative filler.

## CTA hierarchy

Primary: Request Work.

Secondary: See What SteadyMark Helps With, About SteadyMark.

Tertiary/contextual: Request Similar Work, Call SteadyMark, View Make-Readies & Turns.

Buttons should be substantial but not inflated; minimum touch target roughly 44×44 px.

## Header

Integrated, restrained header. Canonical wordmark, Services, About, Request Work. Avoid social clutter, promotional bars, mega-menu behavior, and glass effects.

## Photography

Show property conditions, physical materials, work states, realistic tools, and believable residential/multifamily environments. Images should feel observational rather than promotional.

Default treatment: natural crop, no decorative frame, no heavy overlay, no fake grain, no parallax, no generic rounded cards.

## Service presentation

Do not default the four Service Lines to four identical SaaS cards. Prefer editorial rows, asymmetric grids, broad bands, or image/text pairings.

## Representative Scopes

Reinforce **Condition → Typical Scope → Next Step** through ordered text, restrained rules/geometry, image relationships, and meaningful registration marks. Do not turn it into a cartoon process diagram.

## About

Robert should appear working rather than staged as a contractor archetype. The visual purpose is accountability.

## Request Work

Quieter than Home/Services. The visitor should notice question, field, choice, context, and submit action—not branding. Group fields by meaning and avoid card overload.

## Iconography

Functional, simple linear geometry, consistent stroke. Avoid cartoon tools, house-with-wrench motifs, shield icons, stars, awards, and mixed stock-icon packs.

## Motion

Allowed for orientation, reveal, state transition, and responsive feedback. Typical interface timing 120–220 ms; larger reveals 250–400 ms. Avoid bouncing, springy branding, scroll hijacking, and perpetual movement. Respect reduced-motion preferences.

## Responsive transformation

Desktop may use horizontal relationships; tablet preserves them where healthy; mobile becomes one dominant reading path. Mobile is intentionally composed, not merely collapsed.

## Accessibility

Verify contrast. Steel/Stone may not serve as low-contrast body text. Focus states must be unmistakable. Semantic HTML controls hierarchy; visual scale does not determine heading semantics.

## Performance

Use responsive image formats, intrinsic dimensions, lazy loading below the fold, and only needed font weights. The visual system should not require JavaScript.

## Anti-drift

Do not independently add contractor blue, luxury gold, gradients, heavy shadows, glassmorphism, serif display fonts, generic testimonial sliders, five-star strips, fake statistics, giant icon fields, or decorative slogans.

## Visual priority

**Property / condition → Meaningful scope → Human accountability → Next action → Brand ornament**
